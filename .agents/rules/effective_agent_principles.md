# กฎและหลักการปฏิบัติการของ AI Agent (Effective Agent Principles & Patterns)

เอกสารนี้กำหนดมาตรฐานการทำงานของ Agent และ Subagent ทุกตัวในระบบ เพื่อให้การทำงานมีประสิทธิภาพสูงสุด แม่นยำ และมีความน่าเชื่อถือตามมาตรฐานวิศวกรรม AI สากล (Anthropic, Stanford, Karpathy)

---

## 0. กฎเหล็กสูงสุด: การประเมินเจตนาและการยกระดับคุณภาพงานอัตโนมัติ (Proactive Quality Elevation)
* **ประเมินเจตนาและหยิบ Skill หรือ MCP อัตโนมัติ:** เมื่อผู้ใช้สั่งงานแม้จะเป็นประโยคธรรมดา สั้น ๆ หรือคำสั่งทั่วไป Agent ทุกตัวต้องประเมินเจตนา (Intent) และหยิบ Skill หรือ MCP ที่เกี่ยวข้องขึ้นมาช่วยยกระดับคุณภาพของงานให้เป็นระดับมืออาชีพโดยอัตโนมัติเสมอ
* **ห้ามตอบแบบลวก ๆ หรือใช้ Generic AI Look:**
  - งานออกแบบ UI/UX, เว็บไซต์, Dashboard ➔ ดึง `inspo-design` และ `inspo` MCP อ้างอิงเว็บจริงเสมอ
  - งานอ่าน/สกัดสไลด์ PDF, เอกสารเรียน, ข้อสอบ, สูตรคำนวณ ➔ ดึง `mineru` MCP ถอดสมการ LaTeX และตารางเป๊ะ 100%
  - งานแพ็กโค้ดโปรเจกต์ หรือรวบรวมไฟล์ Wiki ➔ ดึง `repomix` รันออกเป็น XML/Markdown
  - งานท่องเว็บที่ไม่มี API หรือฟอร์มซับซ้อน ➔ ดึง `browser-use` / `playwright` ควบคุมเบราว์เซอร์จริง
  - งานโจทย์ยาก อัลกอริทึมซับซ้อน หรือวางระบบ ➔ ดึง `sequential-thinking` MCP วางแผนทีละสเต็ป
  - งานรายงานวิชาการ โครงงาน หรือใบงาน ➔ ดึง `academic-project-report` หรือ `pdf-worksheet-solver`
* **ทำงานเชิงรุก 100%:** ไม่ต้องรอให้ผู้ใช้เอ่ยชื่อเครื่องมือ ให้วิเคราะห์เป้าหมายแล้วหยิบเครื่องมือที่ดีที่สุดมาใช้ทันที

## 1. ปรัชญาหลัก: Workflows First, Agents Second
* **อย่า Over-engineer:** หากงานมีลำดับขั้นตอนชัดเจน (A -> B -> C) ให้ปฏิบัติตาม Deterministic Workflow ห้ามปล่อยให้ AI ตัดสินใจนอกลู่นอกทาง
* **ลดความเสี่ยงด้วย Guardrails:** ทุก Tool และคำสั่งต้องมีขอบเขตชัดเจน ห้ามรันคำสั่งทำลายข้อมูล ห้ามลบไฟล์งานสำคัญโดยไม่ได้รับอนุญาต

## 2. 5 ท่ามาตรฐานในการทำงาน (The 5 Foundational Agent Patterns)

1. **Evaluator-Optimizer (Critic Loop) - *กฎทองสำคัญที่สุด*:**
   * ห้ามส่งมอบผลลัพธ์แรกที่คิดได้ทันทีในงานสำคัญ (เช่น โค้ดที่มีความซับซ้อน หรือการสรุปเอกสารสอบ)
   * ต้องผ่านขั้นตอน Self-Reflection / Critic: ตรวจทานกับ Checklist ความถูกต้อง ข้อกำหนด และข้อยกเว้นก่อนตอบ

2. **Prompt Chaining (แบ่งงานย่อยร้อยเรียงกัน):**
   * ห้ามแก้ปัญหาขนาดใหญ่ในรอบเดียว ให้แบ่งเป็น: สกัดข้อมูล -> วิเคราะห์ -> วางแผน -> ลงมือทำ -> ตรวจสอบ

3. **Routing (เลือกเครื่องมือและโมเดลให้ตรงงาน):**
   * ส่งคำถามหรืองานให้ตรงกับความเชี่ยวชาญของแต่ละ Agent หรือเครื่องมือ
   * ใช้ `litellm` ช่วยสลับโมเดลหรือทำ Fallback เมื่อเกิดปัญหา Rate limit หรือ Timeout

4. **Orchestrator-Workers (กระจายงานคู่ขนาน):**
   * เมื่อมีงานหลายส่วนที่ไม่ขึ้นต่อกัน ให้กระจายงานให้ Worker หรือ Subagent ทำพร้อมกัน แล้วนำผลลัพธ์มาสังเคราะห์

5. **Parallelization (ระดมมุมมองคู่ขนาน):**
   * รันการตรวจสอบหรือวิเคราะห์หลายแง่มุมพร้อมกันเพื่อหาข้อสรุปที่ดีที่สุด

## 3. การจัดการ Context และความจำ (Context Hygiene & Memory)
* **การส่งต่อ Codebase ขนาดใหญ่:** ให้ใช้เครื่องมือ `repomix` ในการแพ็กโฟลเดอร์หรือคลังความรู้ให้อยู่ในฟอร์แมต XML/Markdown ที่เป็นระเบียบพร้อม Tree Structure และ Token Count
* **ความจำระยะยาว (Persistent Memory):** ใช้งาน `mem0` หรือโครงสร้าง `Wiki LLM` (Markdown-based Zettelkasten) ในการดึงและบันทึกประวัติความจำ เพื่อป้องกันไม่ให้บริบทเก่าสูญหาย
* **เว็บออโตเมชัน (Visual Browsing):** เมื่องานต้องการท่องเว็บที่ไม่มี API หรือมีฟอร์มซับซ้อน ให้ใช้ไลบรารี `browser-use` ควบคุมหน้าจอผ่าน Vision

---

## 4. มาตรฐานความปลอดภัย (Safety & Preservation)
* ยึดถือหลักการ **Zero Data Loss**: ห้ามเขียนทับหรือลบไฟล์ต้นฉบับโดยไม่มี Backup หรือการยืนยัน
* ตรวจสอบสถานะ Git และรัน Test ก่อนสรุปงานเสมอ
